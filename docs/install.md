# Install, update and uninstall

[Back to the README](../README.md)

## One-line install

Windows (PowerShell 5.1 or 7):

```powershell
irm https://raw.githubusercontent.com/marioolf/cortex/main/install.ps1 | iex
```

macOS and Linux (`sh`, with `curl` or `wget`):

```sh
curl -fsSL https://raw.githubusercontent.com/marioolf/cortex/main/install.sh | sh
```

No Go or other dependency is needed. To read a script before running it,
download it and open it: `curl -fsSL https://raw.githubusercontent.com/marioolf/cortex/main/install.sh -o install.sh && less install.sh`,
then `sh install.sh`. (The same files are attached to every release, listed in
`checksums.txt`: `https://github.com/marioolf/cortex/releases/latest/download/install.sh`.)

### What `install.sh` does

1. Finds your system (macOS or Linux; amd64 or arm64) and stops with a clear
   message on anything else.
2. Finds the latest release by following the redirect of
   `github.com/marioolf/cortex/releases/latest` (it does not use the GitHub API,
   so it has no rate limit), or uses `CORTEX_VERSION`.
3. Downloads `cortex_<version>_<os>_<arch>.tar.gz` and `checksums.txt` into a
   temporary folder and checks the SHA-256. On a mismatch it stops and installs
   nothing. The temporary folder is always removed.
4. Puts `cortex` in `~/.local/bin` (no `sudo`). If that folder is not on your
   `PATH`, it prints the line to add for your shell.
5. Starts Cortex once in the background (`cortex run`). Because that is the
   first run, Cortex writes its default config, **registers itself to start at
   login** for that exact file (a launch agent on macOS, an XDG autostart entry
   on Linux) and opens the control panel. If a Cortex is already running from a
   different file, the new one asks it to quit and takes its place (see
   [Update](#update)); a running Cortex that is newer than the one just
   installed is left alone.

If a config file already exists (you installed before), the start does not
touch the login entry; it keeps pointing at the same path, which the installer
replaces in place.

| Variable | Effect |
|---|---|
| `CORTEX_VERSION` | Install this release, for example `v0.1.0`, instead of the latest. |
| `CORTEX_INSTALL_DIR` | Where to put the binary (default `$HOME/.local/bin`). |
| `CORTEX_NO_START` | Set to `1` to install without starting Cortex (and so without registering start at login). |
| `CORTEX_DOWNLOAD_BASE` | For testing: replaces `https://github.com/marioolf/cortex/releases/download`; `CORTEX_VERSION` must be set. |

Pin a version: `curl -fsSL https://raw.githubusercontent.com/marioolf/cortex/main/install.sh | CORTEX_VERSION=v0.1.0 sh`.

### What `install.ps1` does

1. Detects AMD64 or ARM64 and finds the release as above (`$env:CORTEX_VERSION`
   pins one, for example `$env:CORTEX_VERSION = 'v0.1.0'` before the `irm` command).
2. Downloads `cortex_<version>_windows_<arch>.zip` and `checksums.txt` to a
   temporary folder, checks the SHA-256 with `Get-FileHash` (a mismatch stops
   everything) and extracts the zip.
3. Runs `cortex.exe install` from there and waits for it. That command copies
   the program to `%LOCALAPPDATA%\Programs\Cortex\cortex.exe`, adds a Start Menu
   shortcut, registers Cortex to start at login, and starts the installed copy,
   whose panel opens in your browser (a running Cortex from another file is asked
   to quit first). What it printed and its exit code are shown; a non-zero code
   makes the script fail.
4. Removes the temporary folder.

A file that PowerShell downloads has no "Mark of the Web", so SmartScreen does not
show its warning for it. The program is still **not code-signed**: the checksum
only proves that what you got is what the release lists. If you do not want to
run an unsigned program, [build from source](build-and-run.md#build-from-source).

## Manual download and verification

Download the file for your system from the
[Releases page](https://github.com/marioolf/cortex/releases), next to
`checksums.txt` (SHA-256 of every file). Check it:

```sh
sha256sum -c checksums.txt --ignore-missing   # Linux; macOS: shasum -a 256 -c checksums.txt --ignore-missing
```

```powershell
(Get-FileHash .\cortex_0.1.0_windows_amd64.zip -Algorithm SHA256).Hash   # compare with the line in checksums.txt
```

`--ignore-missing` checks only the files you downloaded. Releases are not
code-signed yet, so Windows and macOS may warn about a file downloaded with a
browser; what to expect is described below. Every archive also contains
`THIRD_PARTY_LICENSES.md`: the licences of the Go modules and the Go standard
library that are compiled into the program (generated by `scripts/licenses.sh`,
which CI checks against the committed file).

### Windows (manual)

1. Download `cortex_VERSION_windows_amd64.zip` (most PCs; `arm64` for ARM
   machines such as Copilot+ PCs) and unzip it.
2. Double-click `cortex.exe`. For a file downloaded with a browser (the one-line installer avoids this), Windows SmartScreen will most likely stop it with a
   blue window titled "Windows protected your PC", saying that Microsoft Defender
   SmartScreen prevented an unrecognized app from starting and that running it
   might put your PC at risk, with the publisher shown as "Unknown publisher".
   This happens because the program has no code-signing certificate and is new to
   Microsoft's reputation system, not because SmartScreen found anything in it.
   Click "More info", then "Run anyway", to proceed. If you would rather not run
   a program you cannot verify, build it from source (see [Build from source](build-and-run.md#build-from-source)):
   a program you build yourself is also unsigned, but you know where it came from.
3. Your browser opens the control panel. At the top it says that Cortex is
   running from the folder you unzipped it to; click "Install". Cortex copies
   itself to `%LOCALAPPDATA%\Programs\Cortex\cortex.exe`, adds a Start Menu
   shortcut and registers itself to start at login, then restarts from there and
   opens a new panel. After that you can delete the downloaded file. (Until you
   install, Cortex does not register itself to start at login, because that entry
   would point into your Downloads folder and stop working when the file is
   deleted.) `cortex.exe install` does the same from a terminal.

Cortex has no window of its own: look for its icon in the notification area
(the taskbar's corner, possibly under the "^" arrow). A click opens the panel;
the right-click menu has "Open Cortex", a line saying whether it is running or
paused, "Pause"/"Resume" and "Quit". Pass `-no-tray` to `run` to go without the
icon; if the icon cannot be created, Cortex keeps running without it and logs
why.

### macOS and Linux (manual)

Download `cortex_VERSION_darwin_arm64.tar.gz` (Apple silicon), `darwin_amd64`
(Intel), `linux_amd64` or `linux_arm64`, extract it, put `cortex` in a folder on
your `PATH` (for example `~/.local/bin`) and run `cortex`. The shell script above does these steps for you; `cortex install` itself is Windows-only and says so
on these systems. The
first `run` (the one that finds no config file) registers Cortex to start at
login for the file's location at that moment, so put the binary in its final
place before running it the first time (or pass `-no-autostart`). Later, the
panel's "Start Cortex when I log in" switch registers whichever copy is running
when you turn it on; if you move the binary, turn it off and on again.

The shell installer downloads with `curl`, which does not set the quarantine mark, so Gatekeeper does not
normally get involved. Otherwise, macOS Gatekeeper blocks programs that are not signed and notarized by an Apple
developer when they carry the "quarantine" mark that browsers put on downloads.
A file extracted from the archive with `tar` in the Terminal does not usually get
the mark and just runs; one opened from Finder may be refused with a message
along the lines of "Apple could not verify "cortex" is free of malware". If you
decide to trust the file, you can allow it in System Settings, Privacy & Security
("Open Anyway"), or clear the mark yourself with
`xattr -d com.apple.quarantine /path/to/cortex`. That is your decision to make;
Cortex does not need it for anything else. (The wording above comes from Apple's
documentation and has not been checked on a Mac.)

## Update

Cortex never checks for updates or contacts the Internet. To update, run the one-line installer again, or by hand: on Windows,
download the new release and run the new `cortex.exe` while the installed one is
running (the normal case). The new file asks the running Cortex which program
file it runs from; if that is a different file, it asks it to quit (with the
pairing code from the config file, through `POST /api/ext/quit`), waits up to
about 10 seconds for the port to be free and starts in its place. Its panel then
shows the "Install" banner: click it and the new version replaces the installed
file and restarts from there (`cortex install` does the same from a terminal).
A running Cortex whose version is strictly newer than the new file (compared as
dotted numbers; an unknown version such as `dev` on either side does not count)
is left alone as well, so an old download cannot displace a newer install.
If the running Cortex is the same file, or cannot be asked (a version older
than this feature, which does not say where it runs from, or a pairing code
that does not match), the new file only opens the existing panel and exits, as
before: in that case quit Cortex from the tray or the panel first, then run the
new file. On macOS and Linux, replace the `cortex` file; a different file found
running is replaced the same way, and the login entry points at the file's
path. The panel's footer and `cortex version` show the version you are running.

## Uninstall

On Windows, `cortex uninstall` (run it from the installed copy or from any other
one) quits a running Cortex, removes the start-at-login entry, the Start Menu
shortcut and the installed program. It leaves your settings and always leaves the
vault. `cortex uninstall -purge` also removes the config file and the log (and
their folder if that leaves it empty); the vault is never removed, so delete it
yourself if you want the notes gone. It prints what was removed and what was
left. `-purge` also removes the `summaries-work` folder next to the config file (if
it is a symlink, only the link). The program cannot delete itself while it runs,
so when it is the installed copy, a short-lived helper removes the file a moment
after it exits. `install` and `uninstall` need only the port and the pairing
code from the config file: a config that is damaged or has invalid summaries
settings is reported on stderr and does not stop them. If `install` copies the
program but the Start Menu shortcut or the login entry then fails, it still
goes on with the remaining steps and with starting the installed copy, says that
Cortex was copied and which step failed, and exits with status 1.

If you used the Windows one-line installer, the installed copy is
`& "$env:LOCALAPPDATA\Programs\Cortex\cortex.exe" uninstall`.

On macOS and Linux: turn off "Start Cortex when I log in" in the panel first (that
removes the launch agent or autostart entry), quit Cortex from the panel, then delete the
binary (`rm ~/.local/bin/cortex`, or wherever you put it). The vault and the config
(`~/.config/cortex` on Linux, `~/Library/Application Support/cortex` on macOS) stay until you
delete them.
